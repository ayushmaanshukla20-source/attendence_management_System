## 🌟 Overview

This project provides an intelligent interface to record, update, remove, and calculate attendance for a classroom of students. 

Instead of writing complex code or manually editing files, you can talk to the system in plain English:
- *"Calculate the attendance percentage of Rahul."*
- *"Mark Rahul present on Day 3."*
- *"Mark roll number 102 absent on Day 2."*
- *"Remove Rahul's attendance for Day 4."*
- *"Show the attendance percentage of all students."*
- *"Calculate the class average attendance."*
- *"Show students whose attendance is below 75%."*

## 🧠 How the AI Interacts with Python Tools

### The Core Architectural Principle
**The AI interprets user intent; Python tools execute calculations and database mutations.**

```text
┌───────────────────────┐
│ User Natural Language │  ("Mark Rahul present on Day 3")
└───────────┬───────────┘
            │
            ▼
┌───────────────────────┐
│   Hugging Face LLM    │  (Selects action & extracts arguments)
└───────────┬───────────┘
            │ Strict Action JSON:
            │ {"action": "mark_attendance", "arguments": {"student_identifier": "Rahul", "day": "Day 3", "status": "Present"}}
            ▼
┌───────────────────────┐
│   Python AIAgent      │  (Validates action name & input types)
└───────────┬───────────┘
            │
            ▼
┌───────────────────────┐
│ attendance_tools.py   │  (Python function executes: marks day,
└───────────┬───────────┘   recalculates totals, saves JSON)
            │
            ▼
┌───────────────────────┐
│ Response Synthesizer  │  (Returns human-readable text + structured JSON)
└───────────────────────┘
```

### Safety Guarantees
1. **No `eval()` or `exec()`**: The AI model never executes arbitrary Python code.
2. **Strict Action Whitelist**: Only 7 pre-approved Python functions can be invoked.
3. **No LLM Math Hallucinations**: Percentages and totals are computed strictly using standard Python arithmetic, never generated by the language model.
4. **Safe Persistence**: Updates to `students.json` use atomic file replacement to eliminate data corruption.
5. **Seamless Offline Fallback**: If you don't have a Hugging Face API token configured yet, an internal pattern-matcher seamlessly takes over, allowing full end-to-end testing right out of the box!

## 💾 JSON Data Storage & Integrity

All records are saved in `data/students.json`.

```json
{
  "students": [
    {
      "name": "Rahul",
      "roll_no": "101",
      "attendance": {
        "Day 1": "Present",
        "Day 2": "Absent",
        "Day 3": "Present",
        "Day 4": "Present",
        "Day 5": "Absent"
      },
      "total_days": 5,
      "days_present": 3
    }
  ]
}
```

### Attendance Rules
- **Source of Truth**: The `attendance` dictionary is the sole source of truth.
- **Statuses**: Only `"Present"` and `"Absent"` are valid.
- **Unmarked Days**: If a day has no record, it is treated as *unmarked*, not absent.
- **Totals Recalculation**: Whenever attendance is marked or removed, Python automatically recalculates `total_days` and `days_present` so the data file can never become inconsistent.

## 🚀 Prerequisites & Installation

### 1. Requirements
- **Python 3.10+** (Python 3.11 or Python 3.13 recommended)
- **PowerShell** (Windows) or **Bash** (macOS/Linux)
- **VS Code** (Optional, recommended editor)

### 2. Opening the Project in VS Code
1. Open VS Code.
2. Click **File** > **Open Folder...**
3. Navigate to and select the `attendence` directory.
4. Press ``Ctrl + ` `` to open the integrated PowerShell terminal.

### 3. Setup Virtual Environment (Windows PowerShell)

Run the following commands in your terminal:

```powershell
# Step 1: Create a virtual environment
python -m venv .venv

# Step 2: Activate the virtual environment
.\.venv\Scripts\Activate.ps1

# (If PowerShell blocks script execution, run this once:
# Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope Process)

# Step 3: Upgrade pip and install dependencies
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

## 🔑 Configuring Hugging Face API Token

You can use the system immediately with its built-in offline parser. To enable the cloud Hugging Face Large Language Model:

1. **Create an account** on [Hugging Face](https://huggingface.co/) if you don't already have one.
2. Go to **Settings** > **Access Tokens**: [https://huggingface.co/settings/tokens](https://huggingface.co/settings/tokens)
3. Click **New token**, choose type **Read**, and copy the token string (starts with `hf_...`).
4. In the project folder, create a `.env` file from the template:

```powershell
# In PowerShell:
Copy-Item .env.example .env
```

5. Open `.env` and paste your token:

```ini
HF_TOKEN=hf_YourActualTokenGoesHere
HF_MODEL_ID=Qwen/Qwen2.5-72B-Instruct
```

> ⚠️ **Security Tip**: The `.env` file is included in `.gitignore` so your private API key is never committed to GitHub.


## 🛠️ Troubleshooting Guide

### 1. `Activate.ps1 cannot be loaded because running scripts is disabled`
PowerShell has execution policies enabled by default on Windows. Run:
```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope Process
```
Then run `.\.venv\Scripts\Activate.ps1` again.

### 2. Hugging Face `401 Unauthorized` or Model Loading Error
- Check that your token in `.env` is correct and has **Read** permission.
- If a model is busy, you can change `HF_MODEL_ID` in `.env` to another supported model such as `mistralai/Mistral-7B-Instruct-v0.3`.
- If the token is empty, the system automatically runs with the fast offline fallback engine!

### 3. Student Not Found
Ensure you type the student's name (e.g. `Rahul`, `Priya`, `Amit`, `Sneha`, `Rohan`) or their roll number (`101`, `102`, `103`, `104`, `105`).
